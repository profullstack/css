Documentation / 0.1.0

Make the browser do more.

A small stylesheet that starts with semantic HTML, gives it considered defaults, and makes its interface clear to the next person or agent who reads it.

Install

The source package is ready for its first public npm release. Until then, install from a local checkout:

npm install /path/to/profullstack-css

After publication, install the scoped package and import it from your global stylesheet:

npm install @profullstack/css
@import "@profullstack/css";

The package is plain CSS: no runtime, JavaScript setup, or build step of its own.

Quick start

Use native elements first. Add layout classes only where structure needs a name.

<main class="container stack section">
  <header class="stack" data-space="sm">
    <p class="eyebrow">Workspace</p>
    <h1>Good morning, Alex.</h1>
    <p class="muted">Here’s what needs your attention.</p>
  </header>

  <section class="grid" data-columns="2" aria-label="Summary">
    <article class="card stack" data-space="sm">
      <h2>Projects</h2>
      <p>12 active projects</p>
    </article>
  </section>
</main>

Layout vocabulary

These are the framework’s complete layout primitives. Responsive behavior is built in; use attributes for the few intentional variations.

.container

Centered page width with responsive gutters.

.prose

Readable line length for long-form text.

.stack

Vertical flow. data-space="sm|lg" adjusts its gap.

.cluster

Wrapping row for controls, labels, and navigation.

.grid

Responsive grid. data-columns="2|3|4" sets desktop columns.

.split

Two-column composition that collapses on narrow screens.

.section

Responsive vertical page-section spacing.

Components

Native controls are styled automatically. Use the small component classes for visual roles that HTML does not express on its own.

Buttons

Native <button> is styled by default. Add .button to a link, then choose data-variant="secondary|ghost|danger" if needed.

Cards and status

Use .card, .alert, and .badge when a bordered surface or status label clarifies the content.

ReadyReview

Forms

Label each control. Connect helper and error text with aria-describedby; mark invalid input with aria-invalid="true".

Native patterns

Tables, details, progress, meter, and dialog receive baseline styles. Native behavior remains with the browser or your application.

Color themes

Without an explicit choice, colors follow prefers-color-scheme. Set one attribute on the root element to choose a theme:

<html lang="en" data-theme="dark">

Supported values are light and dark. The application owns the setting control and persistence; CSS supplies the palette.

Customize with tokens

Override the --pf-* variables after importing the framework. The actual values live in css/tokens.css; the JSON catalog lists theme values and token names for tools.

:root {
  --pf-color-primary: #4a42c4;
  --pf-color-primary-hover: #3932a5;
  --pf-radius-md: 1rem;
  --pf-content-width: 78rem;
}
--pf-color-primary--pf-space-4 --pf-font-sans--pf-radius-md --pf-content-width--pf-control-height

Give agents the contract

The package includes a short AGENTS.md and css/manifest.json. The first describes markup and accessibility rules; the second lists supported classes, variants, tokens, themes, and snippets in machine-readable form.
